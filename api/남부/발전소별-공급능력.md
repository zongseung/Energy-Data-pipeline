## ⚠️ 남부 데이터가 아니다 — 전국이다

남부발전이 제공하지만 내용은 **전국 231계열**이다. 설비용량 합계 **82,872 MW** 로
국내 급전 설비 전체 규모다. 남부발전은 그중 일부일 뿐이다.

하루치에 들어 있는 것 (발전사 무관):

```
수력    강릉 칠보 의암 청평 춘천 팔당 화천 대청 소양강 안동 용담 임하 주암 충주 합천
양수    무주 산청 삼랑진 양양 예천 청송 청평
석탄    당진#1~#10(동서)  보령#3~#8·신보령#1~#2(중부)  영흥(남동)  하동#1~#8(남부) …
복합    부산C/C  신인천C/C  영월C/C  안동C/C  한림복합C/C  신세종열병합 …
```

→ **중부·동서·남동 발전소 매칭에도 쓸 수 있다.** 우리 `plants` 는 발전사별로 따로
모았는데 이건 한 테이블에 전국이 들어 있다.

## 요청 파라미터

`serviceKey` · `pageNo` · `numOfRows` · `strSdate` · `strEdate` (YYYYMMDD).
필터 없이 하루 전체(약 231건)가 온다. 하루 계열 수는 조금씩 변한다 (218~231).

## 응답 항목

```
tradedt  stationidx  statioinnm  faccap  supcap  tsupcap  ysupcap  tsupfluct  remark
```

| 항목 | 뜻 | 실측 |
|---|---|---|
| `tradedt` | 거래일 | `20260803` |
| `stationidx` | 발전소 순번 | 1~231. **날짜마다 달라질 수 있다 — 식별자로 쓰지 말 것** |
| `statioinnm` | 발전소명 | **API 오타다** (`station`+`i`). `하동#1`, `부산C/C#1` |
| `faccap` | 설비용량 MW | 하동#1 = 500. **빈 값 있음** (삼척그린#1·#2, 삼척화력#1·#2) |
| `supcap` | ? | **전 계열 0.** 안 쓰이는 컬럼으로 보인다 |
| `tsupcap` | 당일 공급능력 MW | `faccap` 보다 클 수 있다 (부산C/C#1: 설비 450, 공급 480) |
| `ysupcap` | 전일 공급능력 MW | |
| `tsupfluct` | 공급능력 변동 | |
| `remark` | 정비·휴지 사유와 기간 | 231계열 중 28개에 있음 |

`remark` 예:

```
강릉      휴지(2001년 3월~)
화천      #3(25/2/1~26/12/31),#2(7/6~8/9)
청송양수   #1(25/6/2~27/5/31),#2(25/6/2~27/6/30)
영흥#2    (1/1~9/20)
```

→ **설비 가용성·정비 이력이다.** 발전량이 0 인 구간이 고장인지 정비인지 판단하는 데 쓸 수 있다.

## 남부 발전소는 이름 체계가 또 다르다

같은 설비인데 API 마다 표기가 다르다. **호기 분해 수준도 다르다.**

| 이 API | [시간대별 발전량및송전량](시간대별-발전량및송전량.md) | 비고 |
|---|---|---|
| `하동#1` | `하동#1` | 일치 |
| `부산C/C#1` | `부산복합CC#1` | `C/C` vs `CC` |
| `신인천C/C#1` | `신인천복합2_CC#1` | 접두·접미 다름 |
| `영월C/C` (1계열) | `영월복합1CC` (CG1·CG2·CG3·CS1 4계열) | **분해 수준 다름** |
| `남제주복합` (1계열) | `남제주복합 #1 GT`·`#2 GT`·`#1 ST` (3계열) | **분해 수준 다름** |
| `안동C/C#1` | `안동복합CC#1` (CG1·CS1 2계열) | **분해 수준 다름** |
| `한림복합C/C` (1계열) | `한림복합CC` (CG1·CG2·CS1 3계열) | **분해 수준 다름** |
| `신세종열병합` | `신세종복합 #1 GT`·`#1 ST` | 이름·분해 둘 다 다름 |

이 API 는 **CC 축 단위**, PwrGenTran 은 **터빈 단위**다.
용량을 붙이려면 축 단위로 합산하거나 축↔터빈 대응을 손으로 만들어야 한다.
[발전소코드.md](발전소코드.md) 의 `호기코드`(축 단위)가 다리가 될 수 있으나 대조 안 해봤다.

## 우리 스키마 매핑 (초안)

발전량이 아니라 **설비·가용성** 데이터다. `generation` 에는 들어가지 않는다.

```
statioinnm            -> plants 매칭  (이름 체계가 달라 손 매핑 필요)
faccap                -> plants.capacity_mw   (전국 커버 — 중부·동서·남동에도 쓸 수 있다)
tradedt + tsupcap     -> 일별 공급능력 시계열   저장처 미정
remark                -> 정비·휴지 이력        저장처 미정
```

**결정 필요**: 일별 공급능력(231계열 × 약 3,000일 ≈ 70만 행)을 저장할지, 마스터만 뽑을지.

## 미확인

- 제공 시작일 (2015~2018 사이)
- `supcap` 이 왜 전부 0 인지
- `tsupcap` 이 `faccap` 을 넘는 이유 (계절 출력, 출력증대 추정)
- `faccap` 이 빈 계열(삼척그린·삼척화력)의 사유
- `stationidx` 가 날짜 간 안정적인지
