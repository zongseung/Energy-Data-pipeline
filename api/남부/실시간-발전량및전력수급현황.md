## 판정: 이름과 다르다. 실시간도 발전소별도 아니다.

- **실시간 아님** — 하루 1행이다. 3일 요청하면 3건 온다.
- **발전소별 아님** — 남부발전 **회사 전체 집계** 한 줄이다. `plants` 에 붙일 축이 없다.
- **3년 8개월이 비어 있다** (아래).

우리 목표(발전소별 시간별)와 축이 맞지 않는다. **검증용으로만 값어치가 있다** —
[발전실적조회](발전실적조회.md) 71계열 합계와 대조해 계열 누락을 잡을 수 있다.

## 요청 파라미터

`serviceKey` · `pageNo` · `numOfRows` · `strSdate` · `strEdate` (YYYYMMDD).

## 응답 항목

```
ymd  szcurrpwr  powersupply  sparepowers  sparepowerpers  sparepowero  sparepowerpero
```

2026-08-03 실측: `szcurrpwr=10466  powersupply=5939  sparepowers=4527  sparepowerpers=76.22
sparepowero=1352  sparepowerpero=22`

| 항목 | 뜻 | 검증 |
|---|---|---|
| `szcurrpwr` | 공급능력 MW | 남부 설비 12,009 MW 보다 작다 → 정비·휴지 반영한 가용치 |
| `powersupply` | 발전(출력) MW | 71계열 평균출력 5,722 MW 와 근사 (5,939, 3.8% 차) |
| `sparepowers` | 예비력 MW | `szcurrpwr − powersupply` = 10466−5939 = **4527 ✓** |
| `sparepowerpers` | 예비율 % | `sparepowers ÷ powersupply` = 4527/5939 = **76.22 ✓** |
| `sparepowero` | 운영예비력 MW (추정) | |
| `sparepowerpero` | 운영예비율 % (추정) | `sparepowero ÷ powersupply` 로 안 맞는다 (1352/5939=22.76 vs 표시 22). **분모 미확인** |

**단위가 MW 다** — 발전량(MWh)이 아니라 출력이다. 일 대표값인지 최대값인지는 미확인.

## 우리 스키마 매핑

없다. 발전소 축이 없어 `plants`·`generation` 어디에도 안 들어간다.
쓴다면 별도 회사 단위 집계 테이블이고, 그럴 필요가 있는지부터 정해야 한다.

## 미확인

- `powersupply` 가 일 평균인지 최대인지 (71계열 평균출력과 3.8% 차이의 원인)
- `sparepowerpero` 의 분모
- 2022-09-21 ~ 2026-05-31 공백 사유 (원천 중단인지 재공개 누락인지)
