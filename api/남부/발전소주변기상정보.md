## 왜 값어치가 있나 — 발전소 현장 관측이다

우리 기상은 기상청 ASOS 41지점(시간별)이다. 이건 **발전소 부지 안** 관측이고 **5분 단위**다.
태양광 발전량과 붙일 때 지점 거리가 0 이라는 게 ASOS 에 없는 장점이다.

특히 `남제주` 는 우리 `plant_id=3`(`997D` 남제주소내 태양광)과 같은 자리다.

## 사업소별 관측 밀도 — 남제주만 촘촘하다

2026-08-03 하루, 총 444행:

| 사업소 | 하루 행 | 기대(5분×288) | 비고 |
|---|---|---|---|
| **남제주** | **287** | 288 | **99.7% — 진짜 5분 관측** |
| 안동 | 48 | 288 | 17% |
| 부산 | 40 | 288 | 14% |
| 영월 | 24 | 288 | 8% |
| 신인천 | 23 | 288 | 8% |
| 하동 | 22 | 288 | 8% |

→ **남제주 외에는 5분 단위가 아니다.** 시간별로 집계해도 하루 22~48건이면
24시간을 못 채운다. 분석에 쓰기 어렵다.

## 요청 파라미터

`serviceKey` · `pageNo` · `numOfRows` · `strSdate` · `strEdate` (YYYYMMDD).
사업소 필터는 없어 보인다 (미확인). 하루 400~450행이라 `numOfRows` 를 넉넉히 줘야 한다.

## 응답 항목

```
saupso  dddprc  qtep  qhmd  qapr  qdwd  qvwd  qarf
```

| 항목 | 뜻 | 실측 |
|---|---|---|
| `saupso` | 사업소 | `남제주` `안동` `부산` `영월` `신인천` `하동` |
| `dddprc` | 관측시각 | `2026-08-03 23:55:00` (초까지) |
| `qtep` | 기온 ℃ | `27.2` |
| `qhmd` | 습도 % | `69` |
| `qapr` | 기압 hPa | `1007` |
| `qdwd` | 풍향 ° | `77` |
| `qvwd` | 풍속 m/s | `0` |
| `qarf` | 강우 | `0` |

**일사량이 없다.** 태양광 발전량 설명에 제일 중요한 변수인데 빠져 있다.
일사량은 계속 ASOS 에 의존해야 한다 (`docs/asos-solar-radiation-stations.md`).

## 우리 스키마 매핑 (초안)

기상이라 `generation` 이 아니다. ASOS 와 같은 계층에 둬야 한다.

```
saupso  -> 사업소명. plants 와 잇는 표가 필요하다 (남제주 -> plant_id 3 등)
dddprc  -> timestamp (KST 로 보이나 미확인)
qtep/qhmd/qapr/qdwd/qvwd/qarf -> 기상 관측값
```

**결정 필요**: 5분 원본을 저장할지 시간별로 집계할지. 남제주만 받으면 연 10만 행 수준이다.

## 미확인

- `dddprc` 가 KST 인지 (ASOS 는 KST, 동네예보는 UTC — 규약이 섞여 있다)
- 사업소 필터 파라미터 유무
- 남제주 외 5개 사업소의 관측이 성긴 이유 (설비 문제인지 원래 그런지)
- `qarf` 단위 (mm 인지 누적인지)
