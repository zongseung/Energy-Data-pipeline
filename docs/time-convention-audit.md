## 0. 배경 — 한국 전력데이터의 "1~24시" 라벨

한국 전력계통 데이터의 시간 라벨 `1~24`는 **구간종료(hour-ending)** 표기다.
라벨 `N` = 구간 `[N-1시, N시)`. 이 프로젝트는 KPX SMP 수집에서 이미 이 규약을 확정했다
(`fetch_data/smp/smp_collect.py:84`, `# hour-ending -> 구간시작: 라벨 N -> (N-1)시`).

코어 `generation.timestamp`는 **구간시작(interval-start) KST**를 쓴다.
따라서 수집기는 라벨 `N`을 `(N-1)시`로 옮겨야 하고, 옮기지 않은 경로는 **1시간 늦게** 적재된다.

> `generation.timestamp` 컬럼 주석은 현재 "남부=구간시작, KOEN계열=hour-ending→N시 표기"라고
> 되어 있으나 **이 주석은 부정확하다.** 실제로는 남부가 2026-01-01을 경계로 두 규약이 섞여 있고,
> KOEN 계열 중 **태양광만** 구간시작이며 비태양광은 hour-ending 그대로다. (§4 참조)

## 2. 구조 신호 — 첫날에 00시가 있는가

라벨 `N`을 `N시`로 저장하면 **첫 수집일에 00시 행이 없고**(01~23시만), 24시가 익일 00시로 넘어간다.
`(N-1)시`로 저장하면 첫날이 00시부터 시작한다. DB 실측:

| series | source | 첫날 시각 집합 | 범위 | 저장 형태 |
|---|---|---|---|---|
| ekr/solar | api | **0**,1,…,23 | 2019-01-01 00:00 ~ 2025-12-31 23:00 | 0-based |
| namdong/solar | backfill·api | **0**,1,…,23 | 2022-01-01 00:00 ~ | 0-based |
| seobu/wind | backfill | **0**,1,…,23 | 2017-01-01 00:00 ~ 2023-06-30 23:00 | 0-based |
| nambu/solar | api (2026-06-13~) | **0**,1,…,23 | 2026-06-13 00:00 ~ | 0-based |
| nambu/solar | backfill | 1,…,23 (**00시 없음**) | 2015-10-23 **01:00** ~ 2026-06-12 23:00 | 1-based<br>(단 2026-01-01 이후 행은 0-based — §3-2) |
| namdong/thermal·fuel_cell·hydro | backfill·api | 1,…,23 (**00시 없음**) | 2022-01-01 **01:00** ~ …**00:00** | 1-based |
| namdong/wind | backfill·api | 1,…,23 (**00시 없음**) | 2022-01-01 **01:00** ~ …**00:00** | 1-based |
| hangyoung/wind | backfill | 1,…,23 (**00시 없음**) | 2013-01-01 **01:00** ~ 2025-03-01 **00:00** | 1-based |

이 신호는 "**어떻게 저장됐는지**"만 확정해주고 "**원천 라벨이 무엇을 뜻하는지**"는 말해주지 않는다.
1-based 저장이 곧 오류인 것은 원천 라벨이 구간종료일 때뿐이다.
그 마지막 한 걸음을 §3(태양광 물리 검증)과 §4(동일 원천 논증)로 메우며,
메우지 못한 풍력 3계열이 §5의 "불명"이다.

## 3. 데이터 교차검증 — 태양광 일주 곡선

태양광은 시각을 물리적으로 못 박는다. 한국(KST=UTC+9, 표준자오선 135°E, 국토 126~129°E)의
**남중시각은 약 12:24~12:33 KST**다. 구간시작 규약이면 최대 발전 구간은 `[12:00, 13:00)` = **라벨 12**,
에너지 가중 중심시각(centroid)은 약 **12.0**이 된다. 6월 일출은 약 05:11, 일몰은 약 19:40~19:57이므로
`h=5`는 양(+), `h=20`은 0이어야 한다.

### 3-1. 연도별 여름(5·6·7월) 프로파일

정상 발전소만(연·발전소별 argmax 11~13) 발전소별 피크로 정규화 후 평균. h=N 열은 연도 평균.

| operator | 연도 | centroid 범위 | argmax | h=5 | h=6 | h=19 | h=20 | 판정 |
|---|---|---|---|---|---|---|---|---|
| ekr | 2019~2025 | 12.06 ~ 12.21 | **12** | 0.0016 | 0.0610 | 0.0099 | **0.0000** | 구간시작 ✅ |
| namdong | 2022~2026 | 12.10 ~ 12.29 | **12** | 0.0022 | 0.0550 | 0.0064 | **0.0000** | 구간시작 ✅ |
| nambu | 2016~2025 | 12.79 ~ 13.03 | **13** | **0.0003** | 0.0048 | 0.0578 | **0.0027** | 1시간 늦음 ❌ |
| nambu | 2026 | 12.07 | **12** | 0.0035 | 0.0622 | 0.0093 | **0.0000** | 구간시작 ✅ |

남부 2016~2025는 **일출 구간(h=5)이 사실상 0**이고(2017~2025년은 정확히 0.0000, 2016년만 0.0026)
**일몰 이후(h=20)에 발전이 있다** — 구간시작 규약이라면 둘 다 물리적으로 불가능하다.
1시간 당기면 ekr·namdong 곡선과 거의 완전히 겹친다 (2023~2025년 6월, 정상 발전소 정규화 평균):

```
        h:   5      6      7      8      9     10     11     12     13     …    19     20
 ekr(h)  : .0026  .0730  .2365  .4906  .7341  .8993  .9788  1.000  .9861       .0134  .0000
 nambu(h): .0000  .0077  .0882  .2723  .4960  .7163  .8808  .9665  1.000       .0686  .0055
 nambu(h) 를 -1h 시프트 → .0077 .0882 .2723 .4960 .7163 .8808 .9665 1.000 …  ≒ ekr(h-1)
```

### 3-2. 남부의 규약 전환 시점 = **2026-01-01 00:00**

월별 centroid (남부, 원천 이상 발전소 `신인천전망대` 제외):

```
2025-01 13.15 | 2025-04 12.97 | 2025-07 13.09 | 2025-10 12.73 |  ← 1시간 늦음
2025-02 13.23 | 2025-05 12.87 | 2025-08 13.04 | 2025-11 12.78 |
2025-03 13.11 | 2025-06 13.08 | 2025-09 12.93 | 2025-12 12.96 |
-------------------------------------------------------------- 경계
2026-01 12.18 | 2026-04 12.03 | 2026-07 12.24 |                  ← 구간시작(정상)
2026-02 12.30 | 2026-05 11.96 | 2026-08 12.15 |
2026-03 12.14 | 2026-06 12.00 |
```

발전소 15기 **전부**가 같은 경계에서 정확히 1시간 이동한다 (1~3월 centroid, pre-2026 → 2026):

```
신인천 1,2단계 주차장 13.37 → 12.38   부산본부 u1      13.18 → 12.20
신인천해수구취수구   13.46 → 12.47   삼척소내 u1      13.13 → 12.10
부산복합자재창고     12.43 → 11.42   신인천 북측부지  13.37 → 12.37
부산수처리장         13.07 → 12.16   신인천 주차장    13.40 → 12.40
신인천전망대         16.76 → 15.96   부산본부 u2      12.94 → 12.04
남제주소내           13.21 → 12.27   삼척소내 u2      12.95 → 11.89
부산운동장           13.03 → 12.11   삼척소내 u3      13.07 → 12.06
신인천소내           13.81 → 12.98
```

경계 부근 행 구조가 이를 재확인한다:

```
2025-12-30 | 360행 | 시각 0~23
2025-12-31 |  15행 | 시각 0만        ← 2025-12-30 의 "24시"
2026-01-01 | 360행 | 시각 0~23        ← 여기서부터 구간시작 적재
```

즉 레거시(1-based) 적재는 **2025-12-30 24시**에서 끝나고, 신규(0-based) 적재는
**2026-01-01 00시**에서 시작한다. `nambu_backfill.py:262`의 기본 시작일 `20260101`과 일치한다.
**부수 발견: 2025-12-31 01:00~23:00 은 통째로 결측**이다 (§6).

## 4. KOEN 비태양광 — 동일 원천·동일 헤더 논증

남동발전(KOEN) 태양광과 비태양광은 **같은 사이트(koenergy.kr)의 같은 CSV 내보내기**이며
헤더가 문자 그대로 동일하다:

```
pv_data_raw/south_pv_전체_20260301-20260331.csv      (태양광)
  발전구분, 호기, 일자, 1시 발전량(KWh), 2시 발전량(KWh), … , 24시 발전량(KWh)

gen_data_raw/thermal/koen_thermal_20220101-20220131.csv   (화력)
  발전구분, 호기, 일자, 1시 발전량(MWh), 2시 발전량(MWh), … , 24시 발전량(MWh)
```

태양광 경로는 `hour - 1`로 보정하고(`fetch_data/pv/namdong_collect.py:297`),
비태양광 경로는 보정하지 않는다(`fetch_data/gen/transform_gen.py:93-94`).
**같은 원천의 같은 라벨을 서로 다르게 해석**하고 있다는 뜻이고,
그중 태양광 쪽 해석은 §3에서 물리적으로 검증됐다.

→ **KOEN 비태양광(thermal / fuel_cell / hydro)은 1시간 늦다. 보정 `-1시간` 확정.**

남는 가정은 하나뿐이다: *"KOEN이 태양광 메뉴와 비태양광 메뉴에서 시간 라벨을 다른 뜻으로 쓰지 않는다."*
동일 사이트·동일 CSV 내보내기·동일 헤더 포맷이므로 이 가정은 충분히 안전하다고 판단했다.

## 5. 판정이 "불명"인 항목과 그 이유

풍력 3계열은 **물리적 검증 수단이 없다.**
태양광의 일출·남중·일몰 같은 시각 앵커가 풍력에는 존재하지 않고,
풍속 교차검증도 불가능하다 — `data/asos_all_merged.csv`에는 습도·기온·일사만 있고 **풍속 컬럼이 없다.**

아래 "가장 유력한 값"은 **지시가 아니라 관찰**이다. 확정 근거가 없어서 불명으로 남긴 것이므로
**§7 SQL은 이 열을 적용하지 않는다.** 그대로 복사해 시프트하면 358,176행이 잘못된다.

| series | 왜 불명인가 | 가장 유력한 값 (**적용 안 함**) | 무엇이 있으면 확정되나 |
|---|---|---|---|

## 7. Task 3이 그대로 쓸 보정 규칙 (SQL)

`generation g JOIN plants p USING (plant_id)` 기준.

```sql
-- research 배포 뷰의 시간 보정: 원천 hour-ending(라벨 N = 구간 [N-1,N)) 을
-- 구간시작 KST 로 통일한다. 근거: docs/time-convention-audit.md
--
-- ※ generation.source 는 절대 노출하지 않는다(수집 방법 은폐). 아래 SELECT 목록에
--   source 를 추가하지 말 것. 대신 연구원이 조인 없이 쓰도록 plants 속성을 펼쳐 둔다.
CREATE OR REPLACE VIEW research.generation_kst AS
SELECT
    g.plant_id,
    p.operator,
    p.fuel_type,
    p.plant_name,
    g.timestamp - CASE
        -- 남부 태양광: 2025-12-31 이전 레거시 적재분만 1시간 늦다.
        --             2026-01-01 00:00 이후는 이미 구간시작이므로 건드리지 않는다.
        WHEN p.operator = 'nambu'  AND p.fuel_type = 'solar'
             AND g.timestamp < TIMESTAMP '2026-01-01 00:00'          THEN INTERVAL '1 hour'

        -- 남동 비태양광(KOEN CSV 경로): hour-ending 라벨을 무보정 적재.
        WHEN p.operator = 'namdong'
             AND p.fuel_type IN ('thermal', 'fuel_cell', 'hydro')    THEN INTERVAL '1 hour'

        -- 풍력 3계열(namdong/seobu/hangyoung)은 원천 라벨 의미 미확정 → 보정하지 않는다.
        -- 확정되면 아래를 살린다 (§5):
        -- WHEN p.operator IN ('namdong', 'hangyoung') AND p.fuel_type = 'wind'
        --                                                          THEN INTERVAL '1 hour'

        ELSE INTERVAL '0'
    END AS timestamp,
    g.gen_kwh
FROM generation g
JOIN plants p USING (plant_id);
```

보정 대상 행수 (2026-08-10 기준):

| 대상 | 행수 |
|---|---|
| nambu/solar `timestamp < 2026-01-01` | 795,144 / 874,392 |
| namdong/thermal | 953,232 |
| namdong/fuel_cell | 321,216 |
| namdong/hydro | 157,056 |
| **보정 합계** | **2,226,648** |
| 무보정 (ekr·namdong solar·nambu 2026~) | 1,114,584 |
| 보정 보류 (풍력 3계열) | 358,176 |

> 남부 pre-2026 보정 후 범위: 2015-10-23 **00:00** ~ 2025-12-30 23:00.
> 2025-12-31 전일이 비고, 2026-01-01 00:00부터 신규 적재가 이어진다 (§6-1).
