# 전력수요와 수급

전국·제주 계통 수급과 지역난방 열수요. 물리적으로는 demand DB에 있지만 FDW를 거치므로 pv DB 계정 하나로 발전량과 함께 조회합니다.

***

## 수요·수급 데이터 (demand DB, FDW 경유)

**따로 접속하실 필요 없습니다.** 아래 5개는 물리적으로 demand DB에 있습니다. 다만 pv DB의 `research` 스키마로 FDW 연결돼 있으니 **pv DB 계정 하나로 발전량과 함께 조회하고 조인까지 됩니다.** 복제본이 아니라 라이브 프록시라 값도 항상 최신입니다.

```sql
-- 발전량(시간별)과 전국 수요(5분)를 한 쿼리에서 조인 — 접속 전환 없이 그대로 됩니다
SELECT g.timestamp, round(sum(g.gen_kwh)::numeric,0) AS solar_kwh,
       round(avg(d.current_demand)::numeric,0) AS demand_mw
FROM research.generation g
JOIN research.demand_5min d
  ON d.timestamp >= g.timestamp AND d.timestamp < g.timestamp + INTERVAL '1 hour'
WHERE g.fuel_type = 'solar'
  AND g.timestamp >= '2026-08-01' AND g.timestamp < '2026-08-02'
  AND d.timestamp >= '2026-08-01' AND d.timestamp < '2026-08-02'   -- ← 반드시 양쪽에
GROUP BY g.timestamp ORDER BY g.timestamp;
```

> **FDW 조인 주의 — 기간 조건을 양쪽에 거세요.** 위 쿼리에서 `d.timestamp` 조건을 빼면 PostgreSQL이 원격 테이블 132만 행을 통째로 끌어와 2분이 지나도 안 끝납니다. 조인 조건만으로는 범위가 원격까지 내려가지 않습니다. 로컬 뷰와 FDW 테이블을 조인할 때는 **양쪽 테이블 각각에** WHERE 로 기간을 명시하는 것이 규칙입니다.

이 계열의 시간 규약은 pv DB만큼 감사하지 못했습니다. **근거가 없는 컬럼은 시프트하지 않았습니다** — 아래 "무보정" 표기는 게으름이 아닙니다. 확정 근거가 생기기 전까지 임의로 손대지 않겠다고 일부러 내린 결정입니다.

{% hint style="success" %}
`research` 스키마에서 가장 최신인 계열입니다. 10분마다 적재돼 조회 시점 기준 20분 전 데이터까지 들어와 있습니다.
{% endhint %}

| 컬럼                  | 의미                     | 비고                                                                                                                                                                                                      |
| ------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `timestamp`         | KPX 원천 "기준일시"를 그대로 적재  | 구간 라벨인지 순시 시각인지 확정 근거가 없어 무보정                                                                                                                                                                           |
| `current_demand`    | 현재수요 (MW)              |                                                                                                                                                                                                         |
| `current_supply`    | **공급능력** (MW)          | **컬럼명 함정**: 이름은 `current_supply`지만 값은 항상 `current_demand`보다 훨씬 큽니다(예: 105,616 vs 74,850) — "현재 공급되는 양"이 아니라 시스템이 낼 수 있는 총 공급능력입니다                                                                       |
| `supply_capacity`   | **최대예측수요** (MW)        | **컬럼명 함정**: 이름은 `supply_capacity`(공급능력처럼 보임)지만 실제로는 그날의 최대예측수요입니다 — 같은 날 안에서는 값이 일정하게 유지됩니다(위 예: 93,500이 반복). **공급능력이 필요하면 `current_supply`를, 최대예측수요가 필요하면 `supply_capacity`를 쓰세요 — 이름과 의미가 뒤바뀌어 있습니다** |
| `supply_reserve`    | 공급예비력 (MW)             | `current_supply - current_demand`와 대략 일치                                                                                                                                                                |
| `reserve_rate`      | 공급예비율 (%)              | `supply_reserve / current_demand × 100`과 대략 일치                                                                                                                                                          |
| `operation_reserve` | 운영예비력 (MW)             |                                                                                                                                                                                                         |
| `is_holiday`        | 공휴일 여부                 |                                                                                                                                                                                                         |
| `day_type`          | 0=평일, 1=주말(토/일), 2=공휴일 | 공휴일이 최우선 판정(주말+공휴일이면 2)                                                                                                                                                                                 |
