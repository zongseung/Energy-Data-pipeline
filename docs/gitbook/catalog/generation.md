# 발전소와 발전량

발전소 마스터(`research.plants`)와 시간별 발전량(`research.generation`). 이 프로젝트에서 함정이 가장 많은 두 뷰입니다 — 단위·시간 규약·품질 등급을 모르고 쓰면 답이 조용히 틀립니다.

***

### research.plants — 발전소 마스터 + 데이터 품질 등급

발전소당 1행(시계열 아님). 별도 배치 스케줄은 없습니다. 다른 발전 수집기가 신규 발전소를 발견할 때 함께 갱신됩니다.

| 항목     | 값                                                                                                                           |
| ------ | --------------------------------------------------------------------------------------------------------------------------- |
| 행수     | 91 (태양광 45 · 화력 24 · 연료전지 8 · 풍력 10 · 해양소수력 4)                                                                              |
| region | `mainland` / `jeju` — **SMP 뷰의 region(`land`/`jeju`/`unified`)과 코드값이 다릅니다.** SMP와 지역으로 조인하려면 `mainland → land`로 직접 매핑해야 합니다 |

**컬럼**

| 컬럼                                    | 의미                                                | 비고                                                                    |
| ------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------- |
| `plant_id`                            | 발전소 고유 ID                                         | **조인 키는 이것을 쓰세요.** `plant_name`은 유일하지 않습니다(삼척소내 3기, 부산본부 2기 등 동명이 존재) |
| `plant_name`                          | 발전소명                                              |                                                                       |
| `unit_no`                             | 호기 번호                                             | `plant_name`과 함께 써야 유일 식별 가능                                          |
| `operator`                            | 사업자: `nambu`/`namdong`/`seobu`/`hangyoung`/`ekr`  |                                                                       |
| `fuel_type`                           | 발전원: `solar`/`thermal`/`fuel_cell`/`hydro`/`wind` |                                                                       |
| `region`                              | `mainland`/`jeju`                                 | 위 표 참고                                                                |
| `capacity_mw`                         | 정격용량(MW)                                          | 아래 "capacity\_mw 보유율" 참고. 공시값·추정값이 섞여 있어 정밀도 보장 안 함                   |
| `lat`, `lon`                          | 위도·경도                                             | 아래 "좌표" 항목 참고                                                         |
| `is_aggregate`                        | 합계 계열 여부                                          | 아래 "함정 — is\_aggregate" 참고                                            |
| `data_quality`                        | `정상`/`시간별무효`/`전면무효`/`미검증`                         | 아래 "함정 — data\_quality" 참고                                            |
| `hourly_valid_from`                   | 시간별 값을 신뢰할 수 있는 시작일 (NULL이면 근거 없음)                | 아래 "함정 — hourly\_valid\_from" 참고                                      |
| `daily_valid_from` / `daily_valid_to` | 일별 합계를 신뢰할 수 있는 구간                                | `시간별무효`라도 일별 합계는 이 구간에서 유효할 수 있습니다                                    |
| `data_quality_note`                   | 등급 판정 사유 한 줄                                      | 예: ESS 연계 계량 추정, 정오 억제 등                                              |

**data\_quality 분포**

| 등급    | 기수 | 의미                                                                    |
| ----- | -- | --------------------------------------------------------------------- |
| 정상    | 33 | 시간별·일별 모두 사용 가능 (태양광 일주곡선 검사 통과)                                      |
| 시간별무효 | 10 | 시간별 분포를 쓰면 안 됨. 일별 합계는 `daily_valid_from/to` 확인 후 사용                  |
| 전면무효  | 2  | 일별 합계조차 신뢰 불가 (`탑선태양광_1`, `탑선태양광_3` — 원천이 월 단위 값을 일수로 나눠 매일 같은 값을 보냄) |
| 미검증   | 46 | 비태양광 전체. **"깨졌다"가 아니라 "이 감사가 태양광만 봤다"는 뜻** — 정상이라는 보증이 아닙니다           |

**capacity\_mw 보유율** (fuel\_type별, 91기 중 41기만 값 있음)

| fuel\_type | 전체 | capacity\_mw 있음 | 보유율  |
| ---------- | -- | --------------- | ---- |
| solar      | 45 | 3               | 7%   |
| thermal    | 24 | 24              | 100% |
| fuel\_cell | 8  | 6               | 75%  |
| hydro      | 4  | 4               | 100% |
| wind       | 10 | 4               | 40%  |

태양광 45기 중 42기는 `capacity_mw`가 NULL입니다. 발전량을 설비용량으로 나누는 이용률 분석은 태양광에서 거의 불가능하다고 보시면 됩니다.

**좌표(lat/lon)**

| 구분                  | 전체 | 좌표 보유              | 검증 여부                                                                                                                     |
| ------------------- | -- | ------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 태양광                 | 45 | 44 (`율치태양광`만 NULL) | 44기 전부 검증됨 — 단 부지 POI·행정구역 중심의 \*\*근사값(±2km 수준)\*\*이지 정밀 지번 좌표가 아닙니다. ASOS 최근접 지점 매칭에는 충분하나 그 이상 정밀도가 필요한 분석에는 재검증이 필요합니다 |
| 비태양광(화력·연료전지·수력·풍력) | 46 | 40                 | **검증 대상이 아니었습니다 — 신뢰도 불명.** 좌표가 있다고 해서 정확하다는 뜻이 아닙니다                                                                      |

`capacity_confidence` 같은 신뢰도 컬럼은 이 뷰에 없습니다(의미가 오염된 컬럼이라 배포에서 제외했습니다). 좌표를 쓸 때는 위 표의 정성적 설명이 전부입니다.

### research.generation — 시간별 발전량 (시간 보정 완료)

| 항목    | 값                                         |
| ----- | ----------------------------------------- |
| 행수    | 3,246,264                                 |
| 기간    | 2013-01-01 \~ 2026-08-11                  |
| 발전소 수 | 82 (시간별 신뢰 구간이 있는 발전소만. `plants`는 91기 전부) |
| 단위    | `gen_kwh` = **kWh** (아래 "함정 — 단위" 참고)     |

> **이 뷰는 시간별로 믿을 수 없는 구간을 이미 잘라낸 상태입니다.** `data_quality`가 `전면무효`인 발전소는 통째로 빠졌고 `시간별무효`인 발전소는 `hourly_valid_from` 이전 구간이 빠졌습니다. 그래서 `data_quality`로 한 번 더 거를 필요가 없습니다 — 오히려 이중으로 걸면 영흥태양광 #3의 2025-07-01 이후 정상 구간까지 사라집니다.
>
> 왜 잘라냈는가: 등급을 컬럼으로 보여주기만 했더니 아무도 필터를 걸지 않았습니다. 한밤중에 태양광이 발전했다는 답이 그대로 나갔습니다. 야간(21\~04시) 태양광 9,981,569 kWh 중 **99.98%가 위 두 조건에 걸리는 행**이었습니다. 지금은 같은 구간이 1,623 kWh 로 줄었습니다(잔여는 정상 등급 발전소의 계량 노이즈).
>
> **발전소 개수를 세는 질문은 `research.plants`를 보셔야 합니다** — 이 뷰에는 시간별 신뢰 구간이 없는 발전소가 아예 등장하지 않기 때문입니다. 잘려나간 구간도 _일별_ 합계는 유효할 수 있으니(`daily_valid_from`\~`daily_valid_to`), 필요하면 관리자에게 요청하세요.

**갱신 주기** (발전원마다 다릅니다 — 하나의 스케줄이 아닙니다)

| 계열                                               | 스케줄                                                                |
| ------------------------------------------------ | ------------------------------------------------------------------ |
| 남부 태양광 (`operator='nambu'`)                      | 매일 09:30                                                           |
| 남동 태양광 (`operator='namdong', fuel_type='solar'`) | 매월 10일 10:00                                                       |
| KOEN 비태양광 (`operator='namdong'`, 화력·연료전지·해양소수력)  | 매월 10일 10:00                                                       |
| 남동 풍력 (`operator='namdong', fuel_type='wind'`)   | 매월 10일 11:00                                                       |
| 서부·한경 풍력 (`operator IN ('seobu','hangyoung')`)   | **정기 수집 없음.** 서부는 2023-06-30, 한경은 2025-03-01 이후 갱신되지 않은 1회성 적재분입니다 |
| 영암·율치 태양광 (`operator='ekr'`)                     | 매년 1월 8일 04:00                                                     |

**컬럼**

| 컬럼                                                           | 의미                          | 비고                                |
| ------------------------------------------------------------ | --------------------------- | --------------------------------- |
| `plant_id`, `plant_name`, `unit_no`, `operator`, `fuel_type` | `research.plants`와 동일       | 조인 없이 바로 쓰시라고 펼쳐 둔 것              |
| `timestamp`                                                  | 발전 시각                       | **KST 구간시작** (아래 "함정 — 시간 규약" 참고) |
| `gen_kwh`                                                    | 해당 1시간 구간 발전량               | **단위는 kWh** (아래 "함정 — 단위" 참고)     |
| `is_aggregate`, `data_quality`, `hourly_valid_from`          | `research.plants`에서 그대로 가져옴 | 아래 함정 참고                          |

#### 함정 — 시간 규약 (KST 구간시작)

{% hint style="warning" %}
모든 `timestamp`는 **KST 구간시작**입니다. `09:00` 값은 `[09:00, 10:00)` 구간의 발전량이라는 뜻입니다. 원천(KPX/발전사)은 대부분 hour-ending 표기를 씁니다. 1\~24시로 "구간이 끝난 시각"을 라벨에 적는 방식입니다. 뷰가 이걸 이미 구간시작으로 시프트해서 내보냅니다 — **직접 시프트하지 마세요.** 단 **풍력(`fuel_type='wind'`)은 예외입니다.** 원천 라벨이 구간시작인지 구간종료인지 확정할 근거가 없어 보정하지 않았습니다 — **±1시간 불확실**하다고 보고 다루세요.
{% endhint %}

#### 함정 — gen\_kwh 단위

{% hint style="danger" %}
KOEN 비태양광(화력·연료전지·해양소수력) 계열은 **원천 CSV 헤더가 "발전량(MWh)"로 적혀 있지만 실제 저장된 값은 kWh입니다.** 헤더 표기만 보고 `×1000`을 하면 발전량이 1000배로 부풀려집니다. 모든 `fuel_type`에서 `gen_kwh`는 예외 없이 kWh 단위입니다.
{% endhint %}

#### 함정 — data\_quality 4단계

{% hint style="warning" %}
`research.plants`의 등급을 그대로 물려받습니다. 특히 **`미검증`(비태양광 46기)은 "품질이 나쁘다"가 아니라 "이 등급을 매긴 감사가 태양광만 검사했다"는 뜻**입니다. 비태양광 데이터를 함부로 걸러내지 마세요 — 걸러낼 근거가 없다는 것과 정상이라는 것은 다릅니다. 반대로 태양광의 `시간별무효`·`전면무효` 12기는 등급 근거가 명확하니 시간별 분석에서 빼는 것이 맞습니다.
{% endhint %}

#### 함정 — hourly\_valid\_from

{% hint style="danger" %}
`data_quality`만 보고 `시간별무효`를 통째로 걸러내면 **13개월치 정상 데이터를 버립니다.** 반드시 `hourly_valid_from`을 함께 확인하세요.
{% endhint %}

영흥태양광 #3 계열 3기(`plant_id` 20/29/32)는 `시간별무효` 등급이지만 **2025-07-01부터 시간별 값도 정상**입니다. 등급만 보고 거르면 2025-07부터 지금까지가 통째로 날아갑니다.

```sql
-- 시간별 분석에 쓸 수 있는 행만 남기는 올바른 필터
WHERE (data_quality = '정상')
   OR (data_quality = '시간별무효' AND "timestamp" >= hourly_valid_from)
```

#### 함정 — is\_aggregate (지금은 빼면 안 됩니다)

{% hint style="danger" %}
**`WHERE is_aggregate = false`를 넣지 마세요.** 지금은 이중계상이 없고, 넣으면 2019\~2021년 영암 발전량 5,947,954 kWh가 통째로 사라집니다.
{% endhint %}

`plant_id 140`(`영암태양광`)은 `141`(영암1차)·`142`(영암2차)와 같은 사업의 **전체 통합 계열**입니다. 원천이 2019\~2021년 구간에 1차/2차를 구분해 주지 않아 통합값으로만 존재합니다.

| plant\_id | 이름            | 적재 기간                        |
| --------- | ------------- | ---------------------------- |
| 140       | 영암태양광 (사업 전체) | 2019-01-01 \~ **2021**-12-31 |
| 141       | 영암1차태양광       | **2022**-01-01 \~ 2025-12-31 |
| 142       | 영암2차태양광       | **2022**-01-01 \~ 2025-12-31 |

기간이 겹치지 않으므로 지금은 셋을 함께 합산해도 이중계상되지 않습니다. 이 플래그는 "지금 중복"이 아니라 \*\*"겹치면 중복될 계열"\*\*이라는 표시입니다. 2019\~2021 구간에 141·142가 백필되는 순간부터는 반드시 제외해야 합니다.

<summary>이름을 바꾼 이유</summary>

이 행의 이름은 원래 `영암태양광_합계`였습니다. "합계"라는 말 때문에 "다른 행과 중복이니 빼야 할 줄" 알고 실제로 오판한 사례가 나왔습니다. 그래서 사업명 그대로 바꿨습니다.

</details>
