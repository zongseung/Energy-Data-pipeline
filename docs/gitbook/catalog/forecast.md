# 기상 예보

기상청 동네예보 3종입니다. **관측이 아닙니다** — "실제로 어땠나"는 [기상 관측](weather.md)의 ASOS를 쓰세요.

{% hint style="danger" %}
**이 페이지의 시각만 UTC입니다.** 이 프로젝트가 내보내는 다른 모든 시계열(발전량·수요·SMP·ASOS)은 KST입니다. 예보만 규약이 다르고, 이 데이터에서 가장 자주 틀리는 지점입니다. 붙이기 전에 아래 시차 항목을 먼저 읽으세요.

**함수는 원본 CSV의 라벨을 그대로 돌려줍니다. 보정하지 않습니다.** 원천이 무엇을 줬는지가 그대로 보여야 한다고 판단해서 그렇게 뒀습니다. 시차를 옮기는 것은 쓰는 쪽 몫입니다.
{% endhint %}

> 세 예보종 중 `초단기실황`만은 이름 그대로 **관측 실황**이라 리드타임이 없습니다. 다만 원천·경로·시각 규약이 예보와 같아서 이 페이지에 함께 둡니다. 관측이 필요하면 보통은 [기상 관측](weather.md)의 ASOS가 맞습니다.

***

## 예보 3종

기상청 동네예보 3종은 NAS에 CSV로 쌓여 있습니다. **DB에는 적재하지 않습니다.** 단기예보만 690,154개 파일 × 32,576행 ≈ **225억 행**이라 넣을 자리도 없습니다. 전 읍면동 예보는 발전량 연구라는 목적에도 맞지 않습니다. 대신 호출할 때마다 필요한 파일만 읽는 함수를 뒀습니다. 읍면동 1곳 × 요소 1개 × 30개월이 **0.5초**면 읽힙니다.

| 예보종     | 내용        | 리드타임                    | 수집된 시도 |
| ------- | --------- | ----------------------- | ------ |
| `단기예보`  | 3일치 동네예보  | +6 \~ +67시간             | 18     |
| `초단기예보` | 6시간 이내 예보 | +1 \~ +6시간              | 7      |
| `초단기실황` | 관측 실황     | 없음 (`lead_hours`가 NULL) | 10     |

**예보종마다 수집된 지역이 다릅니다.** 단기예보만 전국이고 초단기 2종은 일부 시도뿐입니다. 빈 결과가 나오면 지역을 틀린 게 아니라 그 예보종에 없는 것일 수 있으니 `research.forecast_regions()`로 먼저 확인하세요.

**요소는 예보종마다 다릅니다.** 단기예보는 12종(1시간기온 · 습도 · 풍속 · 하늘상태 · 강수확률 · 1시간강수량 · 1시간적설 · 강수형태 · 일최고기온 · 일최저기온 · 동서바람성분 · 남북바람성분), 초단기실황은 6종(기온 · 습도 · 풍속 · 풍향 · 강수 · 강수형태)입니다. 이름도 다릅니다 — 단기예보의 `1시간기온`이 초단기실황에서는 `기온`입니다. `research.forecast_elements()`로 확인하고 쓰세요.

**기간**: 2023-01 \~ 2025-06

### 쓰는 법

```sql
-- 요소 이름을 모를 때
SELECT * FROM research.forecast_elements('단기예보');

-- 지역 이름을 모를 때 (인자 없이 부르면 시도·시군구, 시도를 주면 읍면동까지)
SELECT * FROM research.forecast_regions('단기예보', '서울특별시', '강남구');

-- 실제 조회 — 기간은 되도록 좁혀서
SELECT * FROM research.forecast('단기예보', '개포1동', '1시간기온', '202301', '202303');
```

| 반환 컬럼                                          | 의미                                                    |
| ---------------------------------------------- | ----------------------------------------------------- |
| `sido`, `sigungu`, `dong_name`, `element_name` | 지역·요소                                                 |
| `grid`                                         | 기상청 격자 `nx_ny` (예: `61_125`)                          |
| `base_at`                                      | **발표 시각** (UTC — 아래 경고 참고)                            |
| `lead_hours`                                   | 예보 리드타임(시간). 초단기실황은 NULL                              |
| `target_at`                                    | **예보 대상 시각** (UTC) = `base_at` + `lead_hours`          |
| `value`                                        | 값 (요소마다 단위가 다릅니다 — 기온 ℃, 습도 %, 풍속 m/s, 하늘상태·강수형태는 코드) |

> **`base_at`과 `target_at`을 구분하세요.** 같은 시각의 예보가 발표 시각마다 여러 번 나옵니다. "가장 정확한 예보"를 원하시면 `target_at`으로 묶고 `base_at`이 가장 늦은 행을 고르세요 — 그게 대상 시각에 가장 가까이서 낸 예보입니다.

> **기간을 생략하면 30개월치를 통째로 읽습니다.** 인자 4·5번(`from_ym`, `to_ym`)은 `YYYYMM` 형식입니다. 되도록 항상 지정하세요. 400개 파일을 넘기면 함수가 거부합니다.

{% hint style="danger" %}
**예보 시각은 UTC입니다. 이 페이지 위쪽의 ASOS와 시간 기준이 다릅니다.** 기상청이 동네예보 자료 안내에 "시간 단위: 협정세계시(UTC, 한국표준시 -9) 사용"이라고 명시해 둔 그대로입니다. 원본 파일의 2열이 UTC 발표시각, 3열이 그 시각으로부터의 편차(`+6` 등)이고, 함수는 이 값을 그대로 돌려줍니다.

**발전량·수요와 붙이려면 `+ INTERVAL '9 hours'`로 옮기세요.** 같은 포털이 주는 자료라도 종관기상(ASOS)은 KST, 동네예보는 UTC입니다. 예보만 다른 규약을 쓴다는 점이 이 데이터에서 가장 자주 틀리는 지점입니다.

보정하지 않으면 예보 라벨상 하루 최고기온이 07시, 최저가 20시에 찍힙니다. 이 모양이 보이면 시차를 안 맞춘 것입니다.
{% endhint %}

{% hint style="warning" %}
**`research.weather_asos`와 맞출 때는 10시간이 필요합니다.** 이론상 9시간이어야 하는데 실측은 10시간에서 가장 잘 맞습니다. 리드타임이 없는 `초단기실황` 기온으로 재보면 10시간에서 평균절대오차가 0.16℃로 떨어지고 9시간은 0.68℃입니다(2024년 1월·6월 동일). 같은 날 값을 나란히 놓으면 차이가 분명합니다.

| 초단기실황(UTC 라벨) | 00시 | 01시 | 02시 | 03시 |
| ------------------ | --- | --- | --- | --- |
| 기온(℃)             | 2.7 | 4.6 | 6.1 | 7.2 |

| ASOS 서울 | 09시 | 10시 | 11시 | 12시 |
| -------- | --- | --- | --- | --- |
| 기온(℃)   | 0.6 | 2.4 | 4.4 | 5.7 |

UTC 00시에 9시간을 더한 09시가 아니라 10시가 맞아떨어집니다. **`research.weather_asos`의 시각이 1시간 밀려 있는 것으로 의심되며 아직 확인하지 못했습니다.** ASOS와 예보를 시각 단위로 비교하는 분석이라면 위 실황 쿼리로 시차를 직접 재고 시작하세요.
{% endhint %}

{% hint style="warning" %}
**같은 예보가 두 번씩 나옵니다.** 원본 CSV에 같은 기간이 두 벌 들어 있어(헤더도 두 번) 행이 약 2배입니다. 합계·평균을 그냥 내면 이중 계산됩니다. `SELECT DISTINCT`로 먼저 접으세요.

**매달 1일은 다음 달 1일과 섞여 있습니다.** 월 파일이 다음 달 1일까지 담는데 함수가 파일 헤더의 연·월 하나로 모든 행을 찍어서, 2월 1일 예보가 1월 1일에 겹쳐 붙습니다. 1일에만 값이 두 갈래로 갈리면 이 때문입니다. 엄밀한 분석에서는 매달 1일을 빼세요.
{% endhint %}

### 실전 예시

**대상 시각마다 가장 늦게 발표된 예보만 뽑기.** 같은 시각을 여러 번 예보하므로, 보통은 대상 시각에 가장 가까이서 낸 예보 하나만 필요합니다.

```sql
WITH fc AS (   -- 원본 중복부터 접는다
    SELECT DISTINCT base_at, target_at, value
    FROM research.forecast('단기예보', '개포1동', '1시간기온', '202301', '202301')
), latest AS ( -- 대상 시각마다 가장 늦은 발표
    SELECT target_at, max(base_at) AS base_at FROM fc GROUP BY target_at
)
SELECT l.target_at + INTERVAL '9 hours' AS target_kst,   -- 발전량·수요와 맞추는 기준
       round(avg(f.value)::numeric, 1) AS forecast_c
FROM latest l JOIN fc f USING (target_at, base_at)
GROUP BY l.target_at
ORDER BY target_kst;
```

**시차를 직접 재기.** 붙일 상대가 정해졌으면 9시간이 맞는지 먼저 확인하세요. 시차를 하나씩 밀어보며 오차가 가장 작은 지점을 찾습니다. 판별이 가장 선명한 것은 리드타임이 없는 `초단기실황`입니다 — 예보가 아니라 관측이라 잘 맞추면 오차가 0.2℃ 아래로 떨어집니다.

```sql
WITH nowcast AS (
    SELECT DISTINCT target_at, value
    FROM research.forecast('초단기실황', '청운효자동', '기온', '202406', '202406')
), lags AS (SELECT generate_series(6, 13) AS lag)
SELECT lag AS 시차_시간,
       round(avg(abs(nowcast.value - w.temperature))::numeric, 2) AS 평균절대오차_c
FROM lags
JOIN nowcast ON true
JOIN research.weather_asos w
  ON w.timestamp = nowcast.target_at + make_interval(hours => lag)
 AND w.station_name = '서울'
GROUP BY lag
ORDER BY 평균절대오차_c;
```

10시간에서 0.16℃로 최소가 되고 9시간은 0.68℃입니다. 기상청 규약대로면 9시간이어야 하니, ASOS를 상대로 할 때는 재보고 쓰세요. 발전량·수요가 상대라면 9시간입니다.

**예보가 얼마나 맞았는지 재기.** 위에서 확인한 시차를 넣고 리드타임별 평균절대오차를 냅니다. 예보 품질을 발전량 예측 모델의 입력으로 평가할 때 씁니다.

```sql
WITH fc AS (
    SELECT DISTINCT base_at, target_at, lead_hours, value
    FROM research.forecast('단기예보', '개포1동', '1시간기온', '202301', '202301')
    WHERE target_at >= '2023-01-02' AND target_at < '2023-02-01'   -- 1일 제외
)
SELECT fc.lead_hours,
       round(avg(abs(fc.value - w.temperature))::numeric, 2) AS 평균절대오차_c,
       count(*) AS 표본
FROM fc
JOIN research.weather_asos w
  ON w.timestamp = fc.target_at + INTERVAL '10 hours'   -- ASOS 기준 시차
 AND w.station_name = '서울'
GROUP BY fc.lead_hours
ORDER BY fc.lead_hours;
```

기온 예보의 평균절대오차는 1℃ 안팎이고 리드타임이 길어질수록 조금씩 커집니다. 예보 오차 자체가 1℃대라 이 쿼리로는 시차 9와 10이 구분되지 않습니다. 시차는 위 실황 쿼리로 정하세요.

**LLM 데모로 물을 때**는 네 가지를 한 문장에 넣으세요. "예보"라는 말(빼면 ASOS 실측을 조회합니다), 읍면동 이름, 정확한 요소 이름, 그리고 기간입니다. 예: `개포1동의 2023년 1월 단기예보 1시간기온을 조회해줘`

**정정된 품질 이슈**: 초단기실황 기온이 한겨울 새벽에 시간당 1\~2℃씩 오르는 구간을 두고 한동안 원천 데이터 결함으로 적어 두었습니다. **원천 문제가 아니라 위의 시차 때문이었습니다.** 청운효자동 2024-01-01 라벨 00\~03시의 2.7 · 4.6 · 6.1 · 7.2℃는 10시간을 밀면 ASOS 서울의 10\~13시 2.4 · 4.4 · 5.7 · 7.3℃와 사실상 같은 값입니다. 새벽이 아니라 늦은 오전이었으니 기온이 오르는 게 정상입니다. 실황값 자체는 ASOS와 잘 맞습니다.
