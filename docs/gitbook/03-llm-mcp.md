# LLM·MCP로 조회

## 먼저 확인: 현재 서비스 모드

현재 서비스의 `energy-db` 도구는 레거시 `run_sql`입니다. 자연어 질문은 가능하지만
모델이 만든 SQL이 별도 승인 화면 없이 즉시 실행됩니다. 도구 목록에 `plan_query`와
`execute_query`가 표시되고 조건·SQL·승인 링크가 먼저 나오는 경우에만 이 페이지의
정식 승인 workflow가 적용됩니다.

## 이렇게 질문하세요

**SQL이나 함수 이름을 알 필요 없이 일상적인 문장으로 입력하면 됩니다.** 대상,
기간, 지표가 빠져 결과가 달라질 수 있으면 도우미가 필요한 내용만 되묻습니다.

| 하고 싶은 일 | 그대로 입력할 예시 | 예상 동작 |
| --- | --- | --- |
| 데이터 존재 확인 | `단기예보 데이터 중 종로구 데이터가 있는지 확인해봐` | 종로구의 읍면동 목록으로 존재 여부 확인 |
| 데이터 받기 | `2023년 서울 종로구의 1시간 기온 데이터를 받고 싶어` | 전체 종로구인지 특정 동인지 확인 후 조회 |
| 발전량 집계 | `구미태양광의 2025년 6월 일별 발전량 합계를 보여줘` | 대상·기간·일별 집계를 조건으로 사용 |
| 모호한 탐색 | `서울 날씨 보여줘` | 관측/예보, 기간, 지역 범위를 질문 |

`research.forecast()`나 `forecast_regions()` 같은 기술 문장을 사용자가 직접 만들
필요는 없습니다. 데이터가 없다는 답을 받았더라도 지역·기간·요소를 확인한 뒤
`어떤 지역과 요소를 조회했는지 SQL과 함께 보여줘`라고 요청해 검증할 수 있습니다.

현재 레거시 mode에서는 되묻기가 모델 지침일 뿐 서버가 강제하지 않습니다. 정식
mode에서는 조건이 부족하면 `plan_query`가 SQL을 만들지 않고 구체화 질문을
반환하므로, 모호한 상태에서 승인 단계로 넘어갈 수 없습니다.

### 대화 이어가기

같은 대화에서는 LibreChat의 대화 기록을 바탕으로 앞서 말한 조건을 이어갈 수
있습니다. 다만 새 대화를 열면 이전 조건을 자동으로 안다고 가정하지 마세요. 현재
설정에는 대화 간 장기 기억 기능이 켜져 있지 않습니다. 정식 workflow가 구체화
질문을 했다면 같은 대화에서 답하고, 30분이 지나 만료됐다면 처음 질문부터 다시
시작합니다.

## 설치 없이 쓰기 — 정식 LibreChat 서비스

브라우저에서 공식 LibreChat 서비스에 로그인하고 채팅 입력창의 MCP(도구) 메뉴에서 `energy-db`를 켜세요. 주소와 계정은 관리자에게 받습니다. 계정은 이 서비스 전용이므로 다른 곳에서 쓰는 비밀번호를 재사용하지 마세요.

정식 전환 후에는 공용 읽기전용 role `demo_ro`로 **사용자가 승인한 SQL만**
실행합니다. 질문, 대화 문맥, 조회에 필요한 결과는 OpenAI 서버로 전송됩니다.
외부로 보내면 안 되는 분석은 직접 SQL 또는 아래의 고급 로컬 경로를 쓰세요.
MongoDB 저장 항목과 보존 기간은
[LLM·MCP 데이터 처리와 투명성](06-llm-transparency.md)에서 확인할 수 있습니다.

{% hint style="warning" %}
논문·보고서의 최종 분석은 LLM 답변만으로 끝내지 마세요. 아래의 조건과 실제 실행 SQL을 직접 SQL로 재현·검증해야 합니다.
{% endhint %}

### 요청·승인 절차

1. 질문이 모호하면 도우미가 발전소·기간·집계·단위처럼 빠진 조건을 **구체화**하도록 하나 이상 물어봅니다.
2. 조건이 정해지면 도우미가 **조건 요약**, 실행 예정 SQL, 30분 동안 유효한 승인 URL을 보여 줍니다. 아직 조회는 실행되지 않습니다.
3. 조건과 SQL을 검토한 뒤 URL에서 **승인** 또는 거절을 누르고, 채팅으로 돌아와 `승인했어` 또는 `거절했어`라고 처리 결과를 알려 줍니다.
4. 승인된 경우에만 `execute_query`가 실행됩니다. 승인 페이지를 누르는 것만으로는 채팅이 자동 재개되지 않으며, 거절하면 조회하지 않습니다.
5. SQL이 한 글자라도 바뀌면 기존 승인은 쓸 수 없으므로 새 조건 요약과 새 승인을 받아야 합니다.
6. 최종 답변에는 조건 요약과 **실제 실행 SQL**이 함께 표시됩니다.

사용자의 최종 확인은 한 번만 받습니다. 승인 뒤 SQL을 다시 만들거나 바꾸지 않고,
MongoDB에 저장된 동일 SQL을 정확히 한 번 점유해 실행합니다. 승인 URL은 다른
사람에게 전달하지 마세요.

정식 서비스의 채팅 미리보기는 최대 **10행**입니다. 결과가 더 많으면
`truncated: true`, 컬럼 요약과 최대 300,000행의 CSV 다운로드 링크가 제공될 수
있습니다. 기본 시간 제한은 60초입니다. 미리보기만 보고 전체 결과를 일반화하지
말고 CSV 또는 직접 SQL로 검증하세요.

### 결과 검증

1. **실제 실행 SQL** — 의도한 발전소·기간·조건과 같은지 확인합니다.
2. **연료 필터** — `research.generation`에는 태양광·풍력·수력·화력·연료전지가 섞여 있습니다. 태양광 조회에 `fuel_type = 'solar'`가 없으면 화력이 섞일 수 있습니다.
3. **단위·시간** — `gen_kwh`는 kWh이고 기본 시간 규약은 KST 구간시작입니다 (09:00 값 = 09~10시 구간). 단, `research.weather_asos.solar_radiation`의 시간 라벨은 구간시작/구간종료 중 무엇인지 아직 미확정이라 보정하지 않았고, 풍력 발전량은 실제 값과 ±1시간 어긋날 수 있습니다.
4. **품질 필터** — 뷰가 이미 적용한 품질 규칙에 `data_quality = '정상'` 또는 `is_aggregate = false`를 다시 덧붙여 정상 데이터를 빼지 않았는지 확인합니다.
5. **잘림 여부** — `truncated: true`이면 기간을 나누거나 직접 SQL로 재현합니다.

## 고급 경로 — 로컬 stdio `run_sql`

로컬 `energy-mcp`는 연구원 PC에서 실행하는 stdio 프로그램입니다. Tailscale에
먼저 연결하고 직접 SQL과 같은 개인 읽기전용 DB 계정을 사용합니다. 이 `run_sql`
경로는 **승인 절차를 거치지 않는 고급·비권장 경로**이며 응답은 최대 **10,000행**입니다.
정식 조회에는 위 LibreChat 서비스를 사용하세요.

### 시작하기 전에

1. 이용조건 서약 완료
2. Tailscale 연결 (`tailscale status`로 확인 — 직접 SQL 가이드 1절 참고)
3. 개인별 DB 계정(role·비밀번호)
4. `uv` 설치 ([docs.astral.sh/uv](https://docs.astral.sh/uv/))

### 1. 로컬 energy-mcp 실행

이 패키지는 아직 PyPI에 올라가 있지 않습니다. 현재는 저장소 로컬 체크아웃에서 실행합니다 (경로는 관리자에게 문의):

```bash
uvx --from /path/to/Energy-Data-pipeline/mcp-server energy-mcp
```

`run_sql`은 `research` 스키마를 읽기전용으로 조회합니다. `energy://schema` 리소스는 뷰·컬럼·설명을 DB에서 읽어 보여 줍니다.

### 2. 서버 등록

Claude Desktop 기준 `claude_desktop_config.json`에 DB별 서버를 등록합니다. 아래 `ENERGY_MCP_DSN`은 플레이스홀더이며, 실제 값을 저장소나 채팅에 남기지 마세요.

```json
{
  "mcpServers": {
    "energy-pv": {
      "command": "uvx",
      "args": ["--from", "/path/to/Energy-Data-pipeline/mcp-server", "energy-mcp"],
      "env": {
        "ENERGY_MCP_DSN": "postgresql://<발급받은_ID>:<발급받은_비밀번호>@<tailnet-host>:5436/pv"
      }
    },
    "energy-demand": {
      "command": "uvx",
      "args": ["--from", "/path/to/Energy-Data-pipeline/mcp-server", "energy-mcp"],
      "env": {
        "ENERGY_MCP_DSN": "postgresql://<발급받은_ID>:<발급받은_비밀번호>@<tailnet-host>:5433/demand"
      }
    }
  }
}
```

서버 프로세스 하나는 DB 하나에만 붙습니다. 두 DB를 모두 쓰려면 항목을 두 개 등록하고 `ENERGY_MCP_DSN`만 다르게 둡니다.

## 직접 SQL로 전환

정식 서비스의 SQL을 재현·검증하거나 복잡한 분석이 필요하면 직접 SQL로 전환하세요. Tailscale 연결과 개인 계정을 그대로 사용합니다. 로컬 stdio `run_sql`이 계속 실패해도 직접 SQL로 재현할 수 있습니다.
