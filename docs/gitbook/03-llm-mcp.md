# LibreChat에서 자연어로 조회

한국어로 질문하면 AI가 조회 조건과 실행할 SQL을 정리해 보여 주고, **내가 승인한 뒤에만** 한 번 실행해서 결과 표와 CSV를 줍니다. 이 페이지는 질문하는 법부터 결과 받기, 막혔을 때까지 차례로 설명합니다. 처음이라면 먼저 [첫 질문 해보기](start/first-query.md)를 따라 해 보세요.

## 한눈에 보기

| 단계    | 내가 하는 일                    | 서비스가 하는 일                              |
| ----- | -------------------------- | -------------------------------------- |
| 1. 질문 | 데이터 종류, 지역, 기간을 적어 질문합니다   | 빠진 조건이 있으면 되묻습니다                       |
| 2. 확인 | 정리된 조건과 SQL을 읽어 봅니다        | 조건, 실행할 SQL, 승인 링크를 보여 줍니다. 아직 실행 전입니다 |
| 3. 승인 | 링크를 열어 다시 확인하고 승인 버튼을 누릅니다 | 승인한 SQL만 한 번 실행합니다                     |
| 4. 결과 | 미리보기와 행 수를 확인하고 CSV를 받습니다  | 결과 표, 행 수, CSV 링크를 보여 줍니다              |

이 서비스는 읽기 전용입니다. 데이터를 고치거나 지울 수 없습니다.

## 시작하기 전에

* 서비스는 연구용 폐쇄망 안에 있어서 먼저 [접속 준비하기](start/access.md)를 마쳐야 합니다. 접속 주소와 키는 이 공개 문서에 적지 않습니다.
* 서비스 주소를 열고 로그인합니다. 처음이라면 회원가입 화면에서 계정을 만드세요. 이름과 이메일은 서약 폼에 적은 것과 같게 씁니다. 개인 DB 비밀번호나 OpenAI API 키를 채팅에 입력할 필요는 없습니다.
* 새 대화를 열고 입력창 근처의 MCP 도구 메뉴에서 `energy-db`를 켭니다. 이 도구를 켜야 데이터를 조회할 수 있고, 안에 `plan_query`와 `execute_query`가 보이면 정상입니다.

{% hint style="warning" %}
도구 목록에 `energy-db`가 없거나 `run_sql` 하나만 보이면 서비스 설정에 문제가 있는 것입니다. 이 페이지의 승인 절차를 진행하지 말고 관리자에게 문의하세요.
{% endhint %}

## 질문 잘 쓰는 법

질문에 아래 다섯 가지가 들어 있을수록 되묻는 횟수가 줄고 결과가 정확해집니다.

| 넣을 것   | 예                      |
| ------ | ---------------------- |
| 데이터 종류 | 태양광 발전량, SMP, 기온 예보    |
| 대상     | 발전소 이름, 지역(시도·시군구·읍면동) |
| 기간     | 2025년 8월, 2024년 전체     |
| 값(요소)  | 1시간기온, 발전량 합계          |
| 집계 단위  | 월별 평균, 일별 합계, 원시 행     |

이런 질문으로 시작해 보세요. 데이터마다 가능한 기간이 다르니 [데이터 카탈로그](04-data-catalog.md)에서 먼저 확인할 수 있습니다.

* 2025년 8월 태양광 발전소별 월 발전량 합계를 보여줘.
* 2024년 하루전시장 SMP의 월별 평균을 알려줘.
* 2025년 7월 전국 전력수요(5분 단위)의 일별 최대값을 보여줘.
* 2026년 4월 WTI 시간별 종가를 CSV로 줘.
* 서울특별시 중구 필동의 2023년 1월 단기예보에서 1시간기온을 월별 평균으로 보여줘.

## AI가 되물을 때

조회 결과가 달라질 만큼 조건이 빠지면 AI가 SQL을 만들지 않고 먼저 되묻습니다. 채팅에서는 `needs_clarification` 상태로 표시되기도 합니다. 빠진 항목에 답하면 기존 질문 계획에 합쳐지니 처음부터 다시 쓰지 않아도 됩니다.

예를 들어 "서울의 기온 예보를 보여줘"라고 물으면 단기예보인지 초단기예보인지, 어느 구·동인지, 어떤 기온 요소와 기간인지 되묻습니다. 읍면동을 모르면 구까지만 답해도 서비스가 실제 읍면동 목록을 확인하고 선택지를 보여 줍니다.

## 조건과 SQL 확인 후 승인하기

조건이 갖춰지면 응답에 정리된 조건, 설명, 실행할 SQL, 승인 링크가 나옵니다. **이 시점에는 SQL이 실행되지 않았습니다.**

1. 조건과 SQL이 요청에 맞는지 읽어 봅니다.
2. 승인 링크를 브라우저에서 엽니다. 표시된 조건과 SQL을 다시 확인한 뒤 승인 버튼을 누릅니다. 승인 페이지는 조회를 실행하지 않습니다.
3. 채팅으로 돌아와 "브라우저에서 승인했습니다. 승인한 조회를 실행해 주세요."라고 입력합니다.

승인한 SQL은 **한 번만** 실행됩니다. 조건을 구체화하는 단계는 시작 후 30분 안에 마쳐야 하고, SQL 계획이 나오면 승인과 실행에 쓸 30분이 새로 시작됩니다. 시간이 지나면 새 질문으로 다시 계획합니다.

## 결과 받기

실행이 끝나면 채팅에 실제 실행한 SQL, 결과 미리보기(처음 10행), 전체 행 수가 나옵니다. 결과가 크면 **CSV 다운로드 링크**가 함께 나오고, 한 번에 최대 30만 행까지 담깁니다. 전체 자료가 필요하면 미리보기를 복사하지 말고 CSV를 받으세요.

* CSV 링크에는 별도 로그인이 없으니 다른 사람에게 공유하지 말고 파일은 바로 내려받으세요. 24시간이 지난 파일은 다음 CSV를 만들 때 정리됩니다. 자세한 보존 동작은 [LLM·MCP 데이터 처리와 투명성](06-llm-transparency.md)에 있습니다.
* 받은 파일에서 기간, 지역, 단위, 행 수가 요청과 맞는지 확인하세요.
* 보고서나 논문에 쓰기 전에는 화면에 표시된 SQL과 [데이터 카탈로그](04-data-catalog.md)를 기준으로 결과를 다시 검증하세요.

## 채팅에서 보이는 도구 이름

AI가 일할 때 채팅에 도구 이름이 보일 수 있습니다. 뜻은 이렇습니다.

| 이름                           | 뜻                                       |
| ---------------------------- | --------------------------------------- |
| `plan_query`                 | 질문을 조건과 SQL 계획으로 정리합니다. 아직 실행하지 않습니다    |
| `execute_query`              | 내가 승인한 SQL을 한 번 실행합니다                   |
| `collect_forecast`           | 없는 기상 예보 월이 있는지 확인하고, 내가 요청하면 수집을 시작합니다 |
| `forecast_collection_status` | 수집 진행 상태를 확인합니다                         |

## 기상 예보 자료 조회

기상청 동네예보는 PostgreSQL 테이블이 아니라 NAS의 CSV 파일에서 읽습니다. 그래서 다른 자료와 다른 점이 있습니다.

* 질문에 **예보종**(단기예보, 초단기예보, 초단기실황), **시도·시군구·읍면동**, **요소**(예: 1시간기온), **시작월과 종료월**이 필요합니다.
* 지역 목록에 이름이 있어도 그 지역·요소·월의 파일이 있다는 뜻은 아닙니다. 서비스가 승인 전에 요청한 모든 월의 파일이 있는지 확인합니다.
* `성남시 수정구`처럼 시군구에 공백을 넣어도 서비스가 실제 등록 이름(`성남시수정구`)으로 맞춰 줍니다.
* 예보 시각은 **UTC**입니다. 다른 자료(대부분 KST)와 합칠 때는 [기상 예보 데이터 안내](catalog/forecast.md)의 시차 주의사항을 읽으세요.

### 예: 원시 CSV 받기

**사용자:** 서울 강남구의 2023년 1월 날씨 예보 자료를 보여줘.

**LibreChat:** 예보종(단기예보·초단기예보·초단기실황), 읍면동, 요소를 지정해 주세요. 요약 집계가 아니라 해당 조건의 원시 행을 CSV로 받을까요?

**사용자:** 단기예보, 서울특별시 강남구 개포1동, 1시간기온입니다. 2023년 1월 원시 행을 CSV로 받겠습니다.

조건이 채워지면 LibreChat이 아래와 같은 SQL 계획을 보여 줍니다. 시도·시군구·읍면동이 모두 들어갔는지, 월 범위가 맞는지 살펴본 뒤 승인하세요.

```sql
SELECT *
FROM research.forecast(
    forecast_type => '단기예보',
    dong => '개포1동',
    element => '1시간기온',
    from_ym => '202301',
    to_ym => '202301',
    sido_filter => '서울특별시',
    sigungu_filter => '강남구'
)
```

### 없는 월을 요청하면

파일이 없는 월을 물으면 서비스는 SQL이나 승인 링크를 만들지 않고 제공 범위를 알려 주며 기간을 다시 묻습니다. 일부 월만 빠진 결과를 완전한 결과처럼 내주지도 않습니다.

**사용자:** 서울 중구 필동의 2021년 1월 단기예보 1시간기온을 조회해 줘.

**LibreChat:** 요청한 `202101` 파일은 없습니다. 확인한 제공범위는 `202301`\~`202507`입니다. 조회할 기간을 다시 지정해 주세요.

제공 범위는 확인한 시점의 값입니다. 최신 월이나 특정 기간은 질문할 때마다 서비스가 실제 파일 목록으로 다시 확인합니다.

### 빠진 월 수집 요청하기

NAS에 없는 월을 새로 받아야 한다면 일반 OpenAI 채팅이 아니라 **에이전트(Agent) 소스**에서 공용 **NAS 기상 조회** 에이전트를 고르세요. 이 에이전트에는 `energy-db`와 수집 절차(Skill)가 연결돼 있습니다.

1. 에이전트가 조건과 기존 파일을 먼저 확인합니다. 이때는 아직 수집하지 않습니다. 자료가 충분하면 수집 없이 위의 조회 순서로 진행합니다.
2. 빠진 월이 있으면 알려 줍니다. **내가 수집을 요청해야** 수집이 시작됩니다.
3. 수집이 시작되면 진행 상태를 확인할 수 있고, 아래 중 하나로 끝납니다.

| 상태            | 뜻                    | 다음에 할 일                                    |
| ------------- | -------------------- | ------------------------------------------ |
| `completed`   | 수집이 끝났습니다            | 파일 월을 다시 확인하고 새 조회를 계획해 승인·실행합니다           |
| `partial`     | 일부만 받았습니다            | 빠진 기간이 남았는지 확인합니다                          |
| `unavailable` | 원천이 유효한 자료를 주지 않았습니다 | 원천에서 제공하는 자료인지 확인합니다. 없는 자료를 만들어 낼 수는 없습니다 |
| `failed`      | 실패했습니다               | 성공으로 보지 말고 관리자에게 문의합니다                     |

수집은 서버에 등록된 기상청 계정으로 실행됩니다. 사용자별 기상청 계정 등록은 아직 지원하지 않습니다. LibreChat 비밀번호, 기상청 API 키, NAS 접근 정보는 채팅에 입력하지 마세요. 에이전트가 보이지 않거나 상태 확인이 되지 않으면 반복해서 시도하지 말고 관리자에게 문의하세요.

직접 만든 에이전트로 쓰려면 **Enable skills**와 **Use all skills**를 켜고 `energy-db` 도구를 추가합니다. 대화 입력창에 `$collect-weather-nas`를 입력해 목록에서 고르면 이 요청에 수집 절차가 적용됩니다. 목록에 없으면 에이전트의 Skills 설정과 관리자 배포 상태를 확인하세요. Skills는 절차를 안내하는 지침이고, 실제 수집은 `energy-db` 도구가 수행합니다.

## 문제가 생겼을 때

| 증상                           | 확인할 내용                                                                      |
| ---------------------------- | --------------------------------------------------------------------------- |
| 서비스 주소가 열리지 않음               | `tailscale status`로 연결을 확인하고, 끊겼다면 [접속 준비하기](start/access.md)의 4단계를 다시 합니다. |
| 로그인이 안 되거나 비밀번호를 잊음          | 관리자에게 비밀번호 재설정을 요청합니다.                                                      |
| `energy-db` 또는 계획 도구가 보이지 않음 | MCP 도구 메뉴에서 서버를 켰는지 확인합니다. `run_sql`만 보이면 관리자에게 운영 설정을 문의합니다.               |
| 추가 질문에 답했는데 진행되지 않음          | 같은 대화에서 답했는지 확인합니다. 30분이 지났다면 새 질문으로 시작합니다.                                 |
| 승인 링크가 만료되었거나 처리되지 않음        | 새 질문을 제출해 조건을 확인하고 새 승인 링크를 받습니다.                                           |
| 지역 목록은 나오지만 시계열이 비어 있음       | 예보종·요소별 자료 범위와 요청한 월을 확인합니다. 지역 목록은 시계열 값의 존재를 보장하지 않습니다.                   |
| 조회 실패 또는 빈 결과                | 조건과 SQL을 확인하고 요청한 기간·지역에 실제 자료가 있는지 봅니다. 자료가 없다면 그 사실이 답변에 표시됩니다.           |
| CSV를 받을 수 없음                 | 링크가 만료됐거나 잘못 복사되지 않았는지 확인합니다. 계속되면 관리자에게 문의합니다.                             |

## 내 질문과 결과는 어디로 가나요

질문, 필요한 대화 문맥, 도구 설명과 실제 조회 결과는 답변을 만들기 위해 OpenAI API로 전송됩니다. 계획 단계에서는 질문, 추가 답변, 스키마 설명으로 SQL 계획을 만듭니다. 민감정보나 외부 제공이 금지된 분석은 입력하지 마세요. 저장·보존 범위는 [LLM·MCP 데이터 처리와 투명성](06-llm-transparency.md)에 설명돼 있습니다.

## 다른 방법이 필요하다면

DB를 직접 조회해야 하거나 Claude 같은 다른 도구로 같은 데이터에 연결하고 싶다면 관리자에게 문의하세요. 이 안내서는 LibreChat 웹 채팅으로 조회하는 방법만 다룹니다.
