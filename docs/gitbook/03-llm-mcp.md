# LibreChat에서 자연어로 조회

LibreChat은 로그인한 연구원이 `energy-db` MCP를 통해 운영 데이터 조회를 요청하는
웹 서비스입니다. 질문을 계획하고 실행할 SQL을 먼저 보여주며, 사용자가 브라우저에서
승인한 뒤에만 PostgreSQL 조회를 시작합니다. 이 경로는 개인 DB 계정을 연결하는
로컬 데모가 아닙니다. 호스팅 서비스가 공용 읽기전용 `demo_ro` 계정으로
`research` 스키마를 조회하며, DB 감사 로그에도 이 계정이 남습니다.

## 접속과 로그인

관리자가 안내한 LibreChat 주소를 엽니다. 접속 주소가 Tailscale 전용이면 먼저
Tailscale에 연결해야 합니다. 주소와 네트워크 접속 방법은 관리자 안내를 따르세요.
이 공개 문서에는 접속 IP나 초대 링크를 싣지 않습니다.

처음 이용한다면 서비스의 회원가입 화면에서 계정을 만들고, 이후 같은 계정으로
로그인합니다. 기관 또는 관리자가 계정을 미리 발급한 경우에는 안내받은 계정으로
로그인하세요. 개인 DB 비밀번호나 OpenAI API 키를 채팅에 입력할 필요는 없습니다.

로그인 후 새 대화를 열고 채팅 입력창 주변의 MCP 도구 메뉴에서 `energy-db`를
활성화합니다. 메뉴에 표시되는 도구 이름은 운영 설정에 따라 달라질 수 있습니다.
운영 workflow가 연결됐는지 확인할 때는 `plan_query`와 `execute_query`가 제공되는지
확인하세요. `run_sql`만 보인다면 이 승인 안내를 진행하지 말고 관리자에게
운영 설정을 문의하세요.

## 질문하고 조건을 구체화하기

질문에는 데이터 종류, 대상 지역, 기간, 요소 또는 지표, 원하는 집계 단위를
가능한 한 넣으세요. 예를 들어 기상 예보에서는 예보종, 시도, 시군구, 읍면동,
요소, 시작월과 종료월을 확인합니다. 발전량에서는 발전소, 기간, 집계 기준을
확인합니다.

정보가 조회 결과를 바꿀 정도로 빠졌다면 MCP가 `needs_clarification` 상태와
추가 질문을 돌려줍니다. 채팅에서 빠진 조건을 답하면 기존 질문 계획에 답변이
합쳐집니다. 예를 들어 “서울의 기온 예보를 보여줘”라고 물으면 단기예보인지
초단기예보인지, 어느 구·동인지, 어떤 기온 요소와 기간인지 되물을 수 있습니다.
필동은 서울 중구, 방배3동은 서울 서초구에 속합니다. 읍면동을 모르면 구까지만
답해도 서비스가 실제 읍면동 목록을 확인하고 선택지를 물을 수 있습니다.

## SQL 확인과 브라우저 승인

조건이 충분하면 응답에 정규화한 조건, 설명, 실행 예정 SQL, 승인 링크가 표시됩니다.
이 시점에는 SQL이 아직 실행되지 않았습니다. 조건과 SQL이 요청에 맞는지 확인하고
승인 링크를 브라우저에서 엽니다. 페이지에 표시된 SQL과 조건을 확인한 다음 승인
버튼을 누르세요. 승인 페이지는 조회를 실행하지 않습니다.

승인 후 LibreChat 대화로 돌아와 승인했다고 알립니다. 그러면 대화 도구가 승인된
workflow의 `execute_query`를 호출합니다. 이 도구는 승인 때 저장한 SQL을 한 번만
실행합니다. 조건 구체화는 시작 후 30분 안에 마쳐야 하며, SQL 계획이 완성되면
승인과 실행에 쓸 수 있는 30분이 새로 시작됩니다.
시간이 지나면 새 질문으로 다시 계획해야 합니다.

## 실제 결과와 CSV 확인

실행이 끝나면 답변에 실제 실행 SQL, 조회 결과 미리보기, 행 수가 표시되고 큰
결과에는 CSV 다운로드 링크가 제공됩니다. 미리보기만 복사하지 말고 전체 자료가
필요하면 CSV를 내려받으세요. CSV 링크는 전달받은 사용자만 접근할 수 있도록
취급하고, 다운로드한 파일에서 기간·지역·단위·행 수가 요청과 맞는지 확인하세요.
보고서나 논문에 쓰기 전에는 표시된 SQL과 데이터 카탈로그를 기준으로 결과를
재검증합니다.

CSV 다운로드의 상세 보존 동작은 [LLM·MCP 데이터 처리와 투명성](06-llm-transparency.md)을
참고하세요. 만료 파일은 24시간 경과 뒤 다음 CSV 내보내기 때 정리됩니다.

## 기상 예보 질문 예시

기상청 예보 시계열은 PostgreSQL 테이블에 적재되지 않고 NAS CSV에서 읽습니다.
지역 목록 CSV는 읍면동 폴더 목록이며, 실제 월별 예보값 CSV와 다릅니다. 목록에
지역 이름이 있어도 요청한 요소와 월의 파일이 존재한다고 볼 수는 없습니다.

예를 들어 다음처럼 질문할 수 있습니다.

> 서울특별시 중구 필동의 2023년 1월 단기예보에서 1시간기온을 월별 평균으로 보여줘.

또는 읍면동이 불분명하면 이렇게 물어볼 수 있습니다.

> 서울특별시 중구의 단기예보 지역 목록을 확인하고, 가능한 동을 알려줘.

필동·방배3동 등 확인한 지역에는 2023년 파일이 있고, 같은 확인 범위에서 2021년
자료는 찾지 못했습니다. 이는 전체 NAS에 대한 완전한 기간표가 아닙니다. 최신 월은
질문에 지정한 예보종·시도·시군구·읍면동·요소로 `forecast_months`가 확인합니다.
승인 전에 요청한 모든 월의 파일이 있는지 검증하며, 빠진 월이 포함되면 기간을
다시 묻습니다. 없는 월을 제외한 부분 자료를 완전한 결과처럼 승인하거나 내보내지
않습니다. 예보종·요소와 조회 방식은 [기상 예보 데이터 안내](catalog/forecast.md)를
참고하세요.

### 원시 CSV를 승인해 내려받는 예시

다음 대화는 예보종·읍면동·요소가 빠진 질문을 구체화해 원시 시계열을 내려받는
흐름입니다.

**사용자:** 서울 강남구의 2023년 1월 날씨 예보 자료를 보여줘.

**LibreChat:** 예보종(단기예보·초단기예보·초단기실황), 읍면동, 요소를 지정해 주세요.
요약 집계가 아니라 해당 조건의 원시 행을 CSV로 받을까요?

**사용자:** 단기예보, 서울특별시 강남구 개포1동, 1시간기온입니다. 2023년 1월 원시 행을 CSV로 받겠습니다.

조건을 채우면 LibreChat은 아래처럼 서버가 생성한 계획을 보여줍니다. 시도·시군구와
읍면동이 모두 포함됐는지, 월 범위가 맞는지 먼저 살펴보세요.

```sql
SELECT *
FROM research.forecast(
    forecast_type => '단기예보',
    dong => '개포1동',
    element => '1시간기온',
    from_ym => '202301',
    to_ym => '202301',
    sido_filter => '서울특별시',
    sigungu_filter => '강남구'
)
```

응답의 승인 링크를 열어 조건과 SQL을 확인하고 승인합니다. 그 뒤 채팅으로 돌아와
“브라우저에서 승인했습니다. 승인한 조회를 실행해 주세요.”라고 입력합니다. 실행
응답에는 결과 미리보기와 행 수, 전체 CSV 다운로드 링크가 표시됩니다. **2026-10-06
이 조합을 확인했을 때 CSV는 32,004행이었습니다.** 이는 개포1동·단기예보·
1시간기온·2023년 1월 조합의 확인값이며 다른 지역이나 월의 행 수를 보장하지
않습니다.

### 제공되지 않는 월을 요청한 경우

예를 들어 다음처럼 묻습니다.

**사용자:** 서울 중구 필동의 2021년 1월 단기예보 1시간기온을 조회해 줘.

서버는 `forecast_months`에서 해당 지역·예보종·요소의 실제 파일 월을 확인하고,
없는 월이 요청에 들어 있으면 실행 가능한 SQL이나 승인 링크를 만들지 않습니다.
확인한 제공범위가 `202301`~`202507`이라면 다음처럼 안내합니다.

**LibreChat:** 요청한 `202101` 파일은 없습니다. 확인한 제공범위는 `202301`~`202507`입니다. 조회할 기간을 다시 지정해 주세요.

**사용자:** 그러면 2023년 1월(`202301`)로 바꿔서 조회해 줘.

새 조건으로 다시 계획하면 SQL과 새 승인 링크가 만들어집니다. 아래 SQL을 확인하고
브라우저 승인 절차를 이어갑니다. 결과 행 수는 이전 요청에서 추정하지 않고 실제
조회 뒤 표시되는 값을 확인하세요.

```sql
SELECT *
FROM research.forecast(
    forecast_type => '단기예보',
    dong => '필동',
    element => '1시간기온',
    from_ym => '202301',
    to_ym => '202301',
    sido_filter => '서울특별시',
    sigungu_filter => '중구'
)
```

이 월 범위는 확인 당시의 제공 정보입니다. `forecast_months`는 월별 파일 목록을
돌려주므로 최신 월이나 특정 기간을 다시 확인할 때는 시점의 목록을 조회합니다.

### NAS에 없는 원천 자료

현재 예보 조회는 NAS에 이미 마운트된 CSV 파일을 읽습니다. 원천 서비스에서 자료를
가져와 NAS에 저장하고 다시 조회하는 자동 수집 절차는 제안된 기능이며 아직
구현되지 않았습니다. 따라서 NAS에 파일이 없으면 LibreChat이나 MCP가 원천 자료를
수집해 채우지 않습니다. 이를 지원하려면 별도의 백엔드 수집기가 원천 서비스에서
자료를 받아 검증하고 NAS에 적재해야 합니다.

원천 서비스 로그인 정보를 채팅이나 질문에 입력하지 마세요. 향후 수집기가 도입되면
관리자가 백엔드에 연결 자격증명을 등록하고 연결 ID로 참조하는 방식으로 다뤄야
합니다. 현재 사용자 화면에 자료 수집 메뉴나 MCP 수집 도구가 제공되는 것은 아닙니다.

예보 SQL의 시간 라벨은 UTC이며 다른 연구 시계열은 대체로 KST입니다. 예보와
발전량·수요를 결합할 때는 [기상 예보 데이터 안내](catalog/forecast.md)의 시차
주의사항을 확인하세요.

## 문제가 생겼을 때

| 증상 | 확인할 내용 |
| --- | --- |
| LibreChat 주소가 열리지 않음 | Tailscale 전용 주소인지 확인하고, 해당하는 경우 Tailscale 연결과 관리자 안내 주소를 확인합니다. |
| `energy-db` 또는 계획 도구가 보이지 않음 | MCP 도구 메뉴에서 서버를 활성화했는지 확인합니다. `run_sql`만 보이면 운영 workflow 연결 여부를 관리자에게 확인합니다. |
| 추가 질문에 답했는데 진행되지 않음 | 같은 대화에서 질문에 답했는지 확인합니다. workflow가 30분을 넘겼다면 새 질문으로 시작합니다. |
| 승인 링크가 만료되었거나 처리되지 않음 | 새 질문을 제출해 조건을 확인하고 새 승인 링크를 받습니다. |
| 지역 목록은 나오지만 시계열이 비어 있음 | 예보종·요소별 자료 범위와 요청한 월을 확인합니다. 지역 목록 CSV는 시계열 값의 존재를 보장하지 않습니다. |
| 조회 실패 또는 빈 결과 | 조건과 SQL을 확인하고, 요청 기간·지역의 실제 자료 유무를 확인합니다. 필요한 자료가 없다면 그 사실을 답변에 명시합니다. |
| CSV를 받을 수 없음 | 링크를 다시 열고, 링크가 만료됐거나 잘못 복사되지 않았는지 확인합니다. 계속되면 관리자에게 문의합니다. |

## OpenAI 전송과 데이터 경계

질문, 필요한 대화 문맥, MCP 도구 설명과 실제 조회 결과는 답변을 만들기 위해
OpenAI API로 전송됩니다. 계획 단계에서는 질문, 추가 답변, 스키마 설명을 사용해
SQL 계획을 만듭니다. 민감정보나 외부 제공이 금지된 분석은 입력하지 마세요.
저장·보존 범위는 [LLM·MCP 데이터 처리와 투명성](06-llm-transparency.md)에
설명돼 있습니다.

## 직접 SQL로 분석하기

재현 가능한 분석이나 더 복잡한 쿼리에는 [직접 SQL로 조회](02-direct-sql.md)를
사용하세요. 직접 SQL 경로는 Tailscale 연결과 개인별 읽기전용 DB 계정을 사용합니다.
LibreChat의 공용 `demo_ro` 계정과 인증·감사 경계가 다릅니다.
