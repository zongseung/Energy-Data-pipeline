# 계통 발전 구성을 발전 실적과 별도 테이블로 둔다

KPX 실시간 발전원별 발전량(계통 전체 5분, MW, 태양광 일부는 추정)을 받기 시작하면서,
이것을 기존 발전 실적(`generation` — 설비 단위, 시간별, kWh, 계량)에 합칠지 정해야 했다.
**별도 테이블(`gen_mix_5min`)로 뒀다.** 둘은 같은 값의 해상도 차이가 아니라 주체(설비 대
계통)·물리량(전력량 대 출력)·시간 단위(1시간 구간 대 5분 순시)·신뢰(계량 대 일부 추정)가
모두 다른 별개의 측정이고, 무엇보다 계통 값이 설비 값을 이미 포함하고 있어서 한 테이블에
두면 `sum()` 한 번에 이중 계산이 나기 때문이다.

## 기각한 대안

`plants` 에 `is_aggregate=true` 인 '전국계통' 의사 발전소를 만들고 `generation` 에 넣는
방법을 검토했다. 이 프로젝트에는 이미 집합 설비를 그렇게 처리하는 관례가 있다(영암태양광).
하지만 `generation` 은 "발전소마다 시간에 한 행"을 전제로 쓰이고 있어서, 5분 행을 넣는
순간 그 전제에 기대던 기존 질의가 조용히 깨진다. MW→kWh 환산으로 단위는 맞출 수 있지만
시간 단위 충돌은 환산으로 해결되지 않는다.

## 결과

연구원이 "지금 전국 태양광"과 "설비별 발전 실적"을 한 질의로 합칠 수 없다. 이건 의도된
것이며, 두 값은 애초에 더하면 안 되는 값이다. 대신 `research.gen_mix_5min` 의 COMMENT 와
데이터 카탈로그에 포함 관계를 명시해 둔다.
